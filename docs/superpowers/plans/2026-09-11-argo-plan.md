# Argo PoC Implementation Plan (indice)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Argo, a proof of concept where small local LLMs (via Ollama) judge whether an npm package version is malicious from a static "dossier", with a measurable experiment (models × prompts P0-P3) and a Streamlit UI.

**Architecture:** File-based pipeline of CLI steps: `dataset build` → `corpus.jsonl`; `dossier build` → one JSON dossier per sample; `run` → `predictions.jsonl`; `eval` → metrics, tables, figures. The UI reads the same files. Malware samples are read only in memory, never executed.

**Tech Stack:** Python 3.11, httpx, pydantic v2, numpy, pandas, matplotlib, streamlit; Ollama 0.33 (local HTTP API); pytest, mypy, ruff.

**Spec:** `docs/superpowers/specs/2026-09-11-argo-design.md`

## Global Constraints

- Python: `/opt/homebrew/bin/python3.11`, virtualenv in `.venv/`. All commands use `.venv/bin/...`.
- Ecosystem: npm only.
- Malware safety: DataDog zips stay encrypted in `data/quarantine/` (password `infected`); content is read in memory with `zipfile`; nothing is ever extracted to disk, installed, or executed. `data/` is gitignored.
- Tests never use real malware: only fake packages built in the test.
- Git: work on branch `feat/poc` (never on `main`). Commit messages are plain: **no `Co-Authored-By` trailer, no mention of Claude or "Generated with"**.
- Quality gate before every commit: `.venv/bin/ruff format argo tests && .venv/bin/pytest -q && .venv/bin/mypy argo && .venv/bin/ruff check --fix argo tests` all green.
- LLM parameters: `temperature=0`, `seed=2026`, `num_ctx=8192`, `num_predict=300` (retry once with `num_predict=600` on invalid JSON).
- Dossier budget: 2000 tokens, estimated as `len(text) // 4`.
- History/test cutoff: `2025-01-01` (DataDog discovery date for malware, publish date for benign).
- Prompts and dossier text in English; UI labels in Italian.
- Ollama base URL `http://localhost:11434`.

## Facts verified on 2026-09-11 (do not re-derive)

- DataDog zips: ZipCrypto (stdlib `zipfile` reads them with `pwd=b"infected"`). Layout: `tmp/<tmpdir>/<pkgdir>/package/<files>` and `tmp/<tmpdir>/<pkgdir>/package_info-<name>-<version>.json` (npm registry document: `time`, `versions`, `dist-tags`, ...). Repo path: `samples/npm/{malicious_intent|compromised_lib}/<dir>/<version>/<YYYY-MM-DD>-<file>.zip`, where `<dir>` is the package name with `/` replaced by `@` (e.g. `@ctrl@tinycolor`).
- GitHub tree API truncates the DataDog repo: list files with a blob-less clone (`git clone --filter=blob:none --no-checkout --depth 1`) + `git ls-tree`.
- Shai-Hulud signatures:
  - W1 (2025-09-14..20): `postinstall: "node bundle.js"`, root `bundle.js` ≈3.7 MB.
  - W2 (2025-11-21..30): `preinstall: "node setup_bun.js"`, root `setup_bun.js` + `bun_environment.js` ≈10 MB.
  - W3 (2026-05-10..25): TanStack — no lifecycle script, `optionalDependencies: {"@tanstack/setup": "github:tanstack/router#<sha>"}`, root `router_init.js` ≈2.3 MB outside `files: ["dist","src"]`; AntV — `preinstall: "bun run index.js"`, root `index.js` ≈500 KB.
